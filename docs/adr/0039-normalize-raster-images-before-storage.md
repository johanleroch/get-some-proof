# Normalize raster images before storage

**Storage amendment:** ADR 0040 moves the normalized files to R2 while retaining the application registry, validation, WebP profiles and ownership rules below. The Convex Storage rationale and Convex-only migration are historical; the new specification governs provider transition and seven-day source retention.

Get Some Proof stores only normalized WebP derivatives for Owner photos, Brand logos, Submitter Photos, Testimonial Images, and custom video thumbnails. Direct uploads are optimized in the browser and rejected unless the stored result satisfies the backend contract; imported images are transformed in a trusted Node action. This hybrid path avoids uploading large originals during normal use without trusting clients to enforce storage limits. Originals are discarded after successful normalization, embedded metadata is stripped after orientation is applied, and logical ownership plus technical transformation data live in an application-owned image asset registry because native Convex Storage exposes opaque IDs rather than folders or custom metadata.

WebP was chosen over AVIF because it preserves transparency, supports reliable browser-side encoding, and keeps one output format across all direct and imported paths. Photos use lossy profiles while logos use lossless or near-lossless encoding. Blob sharing across Projects or owners is deliberately forbidden so deletion, consent withdrawal, and tenant isolation never depend on shared-file reference counting. Existing assets are upgraded through a bounded, idempotent, dry-run-capable migration that requires separate authorization before production execution.
