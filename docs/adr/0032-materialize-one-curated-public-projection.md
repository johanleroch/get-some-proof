# Materialize one curated public projection

The hosted and Embedded Walls consume the same ordered Public Projection and server-rendered card markup rather than applying publication or card rules independently. The projection stores only consented public-safe fields and per-Testimonial overrides; each bounded public page resolves those overrides against the current Wall defaults, so changing defaults is constant-time instead of rewriting an unbounded Wall. New publications and Spam restorations receive the first variable-length fractional order key, while an Owner move atomically changes only the moved projection to a key between validated adjacent neighbors. The key space is dense and grows in length instead of exhausting or requiring a global rebalance. Every move also writes one Organization order version so concurrent moves serialize; a stale target is rejected after retry. Owner curation is paginated in the same order as both public surfaces. This duplicates a small amount of public-safe data, but prevents renderer drift and unbounded customization transactions.

Adding the order key uses a two-phase Convex migration so existing deployments remain deployable. This release keeps `publicOrderKey` optional and ships the resumable internal `migrations:backfillPublicOrderKeys` mutation. Operators deploy this compatible schema and repeatedly pass the returned cursor until `isDone` is true. Each legacy key is derived independently from the prior `publishedAt` order and occupies a reserved range below live fractional keys, so the result is stable across batches and a concurrent new publication remains first. Reordering rejects legacy rows while that backfill is incomplete. A later release may make the field required only after the backfill has completed on every deployment; all newly written projections already receive a key.
